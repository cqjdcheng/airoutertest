# CheapAI 项目结构规范

## 1. 目标

明确 CheapAI 项目的目录职责，避免后续文档、原型、代码、脚本混放。

---

## 2. 根目录约定

项目根目录只保留少量入口级文件和目录。

建议结构：

```text
CheapAi/
├─ docs/          # 所有项目文档
├─ src/           # 所有业务代码
├─ prototype/     # 静态原型与截图
├─ .spec-workflow/# 规格化流程模板与配置
├─ README.md      # 项目总说明
└─ ...
```

---

## 3. 文档目录规范

### 3.1 文档统一放在 `docs/`

所有正式项目文档统一放在：

`docs/`

包括但不限于：

1. 需求文档
2. 功能方案文档
3. 模型测试方案文档
4. 设计规范文档
5. 问卷与调研结果
6. 数据库设计
7. API 设计
8. 开发计划

1. [中转比价网需求.md](./中转比价网需求.md)

5. [技术选型决策记录.md](./技术选型决策记录.md)

建议按“主题明确、中文直观、避免缩写”命名，例如：

1. `用户端设计规范-Apple风格参考.md`
2. `数据库设计-核心表结构.md`
3. `API设计-用户端与后台.md`

不建议：

1. `doc1.md`
2. `final_v2_new.md`
3. `temp.md`

## 4. 代码目录规范

### 4.1 所有业务代码统一放在 `src/`

所有正式代码统一放在：

`src/`

包括但不限于：

1. 用户端前端代码
2. 管理端前端代码
3. API 服务
4. Worker
5. 数据模型
6. 工具函数
7. 配置代码

### 4.2 推荐代码结构

建议按职责拆分：

```text
src/
├─ backend/
│  ├─ CheapAI.Api/              # ASP.NET Core Web API 入口
│  ├─ CheapAI.Application/      # 应用服务、DTO、用例编排
│  ├─ CheapAI.Domain/           # 领域模型与规则
│  ├─ CheapAI.Infrastructure/   # SqlSugar、Redis、存储、外部适配
│  └─ CheapAI.BackgroundJobs/   # Hangfire 任务、抓取、测试、聚合
├─ frontend/
│  ├─ web-public/               # 用户端 Next.js
│  └─ web-admin/                # 管理端 React + Ant Design Pro
└─ scripts/                     # 开发脚本、部署脚本、数据脚本
```

### 4.3 当前正式技术映射

目录与技术栈的对应关系如下：

1. `src/backend/`
   - `.NET 10 LTS`
   - `ASP.NET Core Web API`
   - `SqlSugar`
   - `Hangfire`
2. `src/frontend/web-public/`
   - `Next.js App Router`
   - `React`
   - `TypeScript`
3. `src/frontend/web-admin/`
   - `React`
   - `Ant Design Pro`
   - `Umi Max`
   - `TypeScript`

补充约定：

1. `web-public` 和 `web-admin` 是两个独立前端工程
2. 不建立共享前端模板、共享组件库或共享 UI 包
3. 如果未来需要共享，只允许共享后端协议事实，不作为本轮默认结构
4. 各前端工程和脚本工具的包依赖必须安装在各自目录，不得安装到仓库根目录

### 4.4 Node.js 依赖目录规则

当前 Node.js 依赖目录边界如下：

1. `src/frontend/web-public/`
   - 用户端依赖
   - 独立 `package.json`
   - 独立 `node_modules`
2. `src/frontend/web-admin/`
   - 管理端依赖
   - 独立 `package.json`
   - 独立 `node_modules`
3. `tools/`
   - 脚本工具依赖
   - 独立 `package.json`
   - 独立 `node_modules`

禁止事项：

1. 在仓库根目录安装 Node.js 包
2. 在仓库根目录保留 `node_modules`
3. 用一个根级 `package.json` 承担多个独立工程的依赖

详细执行规范见：

`依赖安装规范.md`

---

## 5. 原型目录规范

静态原型和截图保留在：

`prototype/`

用途：

1. 做信息架构验证
2. 做交互和界面方向确认
3. 作为前端实现参考

注意：

1. `prototype/` 不是正式前端代码目录
2. 原型中的 HTML/CSS 只作为设计参考，不作为生产代码直接上线

---

## 6. 后续执行规则

后续开发默认遵循以下规则：

1. 新增正式文档，放 `docs/`
2. 新增正式代码，放 `src/`
3. 新增原型或设计演示，放 `prototype/`
4. 不再把正式需求和方案文档散落在根目录
5. 后续技术实现默认遵守 `技术开发规范.md`
6. 用户端界面实现默认遵守 `用户端设计规范-Apple风格参考.md`

---

## 7. 当前结论

从现在开始，CheapAI 的目录职责明确为：

1. `docs/`
   - 放文档
2. `src/`
   - 放代码
3. `prototype/`
   - 放原型

后续用户端界面实现，应同时遵守：

1. 目录规范
2. 设计规范
