# CheapAI 现有数据结构文档

更新时间：2026-05-14

本文档描述当前数据库和 DTO 的实际数据结构。字段以当前代码和初始化 SQL 为准。

## 1. 设计原则

1. 模型展示名和请求名必须拆分。
2. 模型必须关联模型供应商。
3. 第三方目录原始 ID 必须保留，避免丢失 OpenRouter 等数据源的唯一标识。
4. 用户端展示字段和后台维护字段可以不同，但必须有明确映射。
5. 报价匹配优先使用 `request_name`，再回退使用 `official_model_id`。

## 2. 核心模型字段口径

| 业务概念 | 数据库字段 | DTO 字段 | 示例 | 说明 |
|---|---|---|---|---|
| 模型名称 | `display_name` | `displayName` / `modelName` | `GPT 5.5` | 用户端和后台展示名 |
| 模型请求名称 | `request_name` | `requestName` | `gpt-5.5` | 实际请求中转接口时使用 |
| 第三方原始 ID | `official_model_id` | `officialModelId` | `openai/gpt-5.5` | OpenRouter 等来源的原始模型 ID |
| 模型供应商 | `provider_id` | `providerId` | `1` | 关联 `model_providers.id` |
| 兼容厂商名 | `vendor` | `vendor` | `OpenAI` | 兼容旧数据和外部导入 |
| 接口类型 | `api_type` | `apiType` | `openai` | 当前支持 `openai` / `anthropic` |
| 模型说明 | `description` | `description` | 文本 | 来源于抓取或手工维护 |
| 热门模型 | `is_hot` | `isHot` | `true` | 控制用户端首页展示 |
| 排序 | `sort_order` | `sortOrder` | `1000` | 越小越靠前 |

1. OpenRouter 原始 ID 写入 `official_model_id`。
2. OpenRouter 原始 ID 最后一段写入 `request_name`。

4. Anthropic/Claude 模型写入 `api_type = 'anthropic'`。
5. 其他模型默认写入 `api_type = 'openai'`。

报价匹配规则：

1. 表单选择已有模型时直接使用 `model_id`。
2. 抓取价格时优先用抓取出的 `requestName` 匹配 `models.request_name`。
3. 如果未匹配，再用 `officialModelId` 匹配 `models.official_model_id`。
4. 未匹配时允许自动创建模型，并写入 `request_name` 和 `api_type`。

### 6.4 关键业务关系

1. `models.provider_id` 关联 `model_providers.id`。
2. `relay_offers.site_id` 关联 `relay_sites.id`。
3. `relay_offers.model_id` 关联 `models.id`。
4. `test_records.site_id` 对应站点，用户自测无法匹配时可为 `0`。
5. `test_records.model_id` 对应模型，用户自测无法匹配时可为 `0`。
6. `risk_evidences.test_record_id` 可关联触发风险的测试记录。
7. `model_ranking_snapshots` 是公开排行快照，不直接作为主数据编辑。
8. `site_submissions` 是用户提交线索，审核后可人工转换为 `relay_sites`。
9. `articles.category_id` 可关联 `article_categories.id`。
10. `refresh_tokens.admin_user_id` 关联 `admin_users.id`。

### 6.5 当前模型数据清洗口径

OpenRouter 数据进入 `models` 时必须执行以下清洗：

| 输入 | 输出字段 | 规则 |
|---|---|---|
| `openai/gpt-5.4` | `official_model_id` | 原样保留 |
| `openai/gpt-5.4` | `request_name` | 取最后一段 `gpt-5.4` |
| `OpenAI: GPT-5.4` | `display_name` | 去掉供应商前缀，保留 `GPT-5.4` |
| `openai` | `model_providers.slug` | 供应商 slug |
| `OpenAI` | `model_providers.name` | 供应商名称 |
| Claude / Anthropic | `api_type` | 写入 `anthropic` |
| 其他模型 | `api_type` | 默认写入 `openai` |

### 6.6 数据安全口径

1. 用户自助测试提交的 API Key 不写入任何表。
2. Refresh Token 仅保存哈希值。
3. 测试记录只保存必要摘要、耗时、token 统计、风险分和检测项。
4. 风险证据 JSON 属于后台诊断数据，公开端只展示摘要。
5. 报价和排行以快照为准，避免公开端实时拼接产生高成本查询。
