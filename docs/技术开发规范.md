# CheapAI 技术开发规范

## 1. 文档目标

本文档用于正式确定 CheapAI 项目的技术栈、工程结构、运行架构和开发约束。

本文档是项目级定案文档，明确以下内容：

1. 后端技术栈
2. 用户端技术栈
3. 管理端技术栈
4. 数据库与缓存技术
5. 调度与后台任务技术
6. 代码目录结构
7. 部署方式

说明：

1. 本文档只定义技术基座
2. 本文档不定义具体 API 路由和接口字段
3. API 详细边界放到后续“功能详细设计文档”
4. 用户端与管理端按完全独立前端工程设计，不建立共享前端模板

---

## 2. 技术栈总览

截至 `2026-05-11`，CheapAI 项目正式采用以下技术栈：

### 后端

1. `.NET 10 LTS`
2. `ASP.NET Core Web API + Controllers`
3. `SqlSugar`
4. `Hangfire`
5. `Serilog`
6. `FluentValidation`
7. `Swagger / OpenAPI`

1. `MySQL 8.4 LTS`
2. `Redis 7+`

### 用户端

1. `Next.js App Router`
2. `React`
3. `TypeScript`
4. `TanStack Query`
5. `Tailwind CSS`
6. `CSS Variables + Design Tokens`
7. `ECharts`

### 管理端

1. `React`
2. `Ant Design Pro`
3. `Umi Max`
4. `TypeScript`

### 部署

1. `Linux`
2. `宝塔`
3. `Docker`
4. `Docker Compose`

## 3. 技术选型结论

## 3.1 后端框架

正式采用：

`ASP.NET Core Web API`

采用方式：

1. 使用原生 ASP.NET Core
2. 保留成熟分层结构
3. 不引入重型业务框架

不采用：

1. `Furion`
2. `ABP`
3. 极简 API 方案

原因：

1. 已明确要求保留原生 `ASP.NET Core`
2. 原生方案控制力强，适合中型数据产品
3. 不提前绑定到重型业务框架

---

## 3.2 ORM

正式采用：

`SqlSugar`

规则：

1. 数据访问层统一使用 `SqlSugar`
2. 不混用 `EF Core`
3. 不混用 `Dapper`
4. 不允许一个项目内出现多套主 ORM

---

## 3.3 数据库

正式采用：

`MySQL 8.4 LTS`

用途：

1. 主业务数据库
2. 站点、模型、报价、测试记录、风险证据、提交审核等核心结构化数据

规则：

1. 所有核心业务数据以 MySQL 为准
2. 首期不拆第二主数据库

---

## 3.4 缓存与中间件

正式采用：

`Redis 7+`

用途：

1. 热点缓存
2. 排行缓存
3. 自助测试限流
4. 分布式锁
5. 临时状态存储

规则：

1. Redis 不是主数据库
2. Redis 中的数据必须可丢失可重建

---

## 3.5 用户端技术

正式采用：

`Next.js App Router + React + TypeScript`

原因：

1. React 主流生态成熟
2. 对 SEO 友好
3. 支持 Metadata、SSR、ISR
4. 适合榜单页、站点详情页、搜索页等公开内容页面

配套：

1. `TanStack Query`
2. `Tailwind CSS`
3. `CSS Variables + Design Tokens`

规则：

1. 用户端必须遵守 `用户端设计规范-Apple风格参考.md`
2. 用户端不引入后台风格组件库
3. 榜单页、详情页、搜索页优先 SSR / ISR

---

## 3.6 管理端技术

正式采用：

`React + Ant Design Pro + Umi Max + TypeScript`

原因：

1. 管理端优先成熟实现
2. 表格、表单、筛选、权限页、任务页交付效率高
3. 和 .NET Web API 的 REST 配合成熟

不采用：

1. `Blazor`
2. `Next.js 承担后台`

原因：

1. Blazor 技术统一性强，但后台模板成熟度和交付效率不如 Ant Design Pro
2. 管理端是高密度数据后台，不适合为了技术统一牺牲交付速度

---

## 3.7 任务调度与后台任务

正式采用：

`Hangfire`

用途：

1. 定时抓价格
2. 定时测试站点模型
3. 风险重算
4. 补测任务
5. 同步第三方榜单

原因：

1. 成熟
2. 可观测
3. 有 Dashboard
4. 更适合需要后台运维感知的项目

规则：

1. 任务执行与 API 服务解耦
2. Hangfire Dashboard 仅后台管理员可见

---

## 3.8 日志与观测

正式采用：

1. `Serilog`
2. 结构化日志

规则：

1. API 日志、任务日志、抓取日志、测试日志统一结构化
2. 敏感字段必须脱敏
3. 用户自助测试中的 Key 不得明文写日志

---

```text
CheapAi/
├─ docs/
├─ src/
├─ prototype/
├─ .spec-workflow/
├─ README.md

```

## 4.2 正式代码结构

```text
src/
├─ backend/
│  ├─ CheapAI.Api/

│  ├─ CheapAI.Domain/

│  └─ web-admin/
```

## 4.3 后端模块职责

### `CheapAI.Api`

1. API 入口
2. 认证鉴权
3. Swagger
4. 全局异常处理
5. 参数绑定

### `CheapAI.Application`

1. 应用服务
2. DTO
3. 用例编排
4. 业务流程协调

### `CheapAI.Domain`

1. 领域模型
2. 枚举
3. 领域规则
4. 核心业务概念

### `CheapAI.Infrastructure`

1. SqlSugar 仓储
2. Redis 封装
3. 文件存储
4. 第三方客户端
5. 外部服务适配

### `CheapAI.BackgroundJobs`

1. Hangfire Job
2. 抓取任务
3. 定时测试
4. 风险计算
5. 聚合刷新

## 4.4 前端模块职责

### `web-public`

1. 榜单页
2. 站点详情页
3. 自助测试页
4. 站点提交页
5. 模型能力榜页

规则：

1. 独立 `package.json`
2. 独立 Next.js 配置
3. 独立 Tailwind 配置
4. 独立环境变量
5. 不依赖管理端模板
6. 依赖只允许安装在 `src/frontend/web-public/`，不得安装到仓库根目录

### `web-admin`

1. 站点管理
2. 模型管理
3. 价格抓取管理
4. 测试任务管理
5. 风险中心
6. 审核流

规则：

1. 独立 `package.json`
2. 独立 Umi / Ant Design Pro 配置
3. 独立环境变量
4. 不依赖用户端模板
5. 依赖只允许安装在 `src/frontend/web-admin/`，不得安装到仓库根目录

### `tools`

1. 开发辅助脚本
2. 本地验收脚本
3. 截图与自动化工具脚本

规则：

1. 如需 Node.js 依赖，独立维护 `tools/package.json`
2. 脚本依赖只允许安装在 `tools/`
3. 不允许把脚本工具依赖安装到仓库根目录

## 5. 访问方式与认证

## 5.1 访问域名

正式采用：

独立子域名

建议示例：

1. 用户端：`www.example.com`
2. 管理端：`admin.example.com`
3. API：`api.example.com`

原因：

1. SEO 与后台天然隔离
2. 缓存边界更清晰
3. 安全策略更好控制
4. 运维与 Nginx 转发更清楚

## 5.2 认证范围

1. 用户端默认匿名访问
2. 只有管理端需要登录

## 5.3 管理端认证方式

正式采用：

1. `JWT Access Token`
2. `HttpOnly Refresh Token`

---

## 6. 前端实现规范

## 6.1 用户端

用户端必须遵守：

1. 使用 `Next.js App Router`
2. 使用 `React + TypeScript`
3. 使用 `Tailwind CSS`
4. 使用 `CSS Variables + Design Tokens`
5. 遵守 `用户端设计规范-Apple风格参考.md`
6. 不建立或依赖共享前端模板

规则：

1. 榜单页、详情页、搜索页优先 SSR/ISR
2. 页面元数据使用 Next.js Metadata
3. 公开页面不得退化为纯 CSR
4. 安装依赖时必须在 `src/frontend/web-public/` 内执行，或使用 `pnpm --dir "D:/project/CheapAi/src/frontend/web-public" ...`

## 6.2 管理端

管理端必须遵守：

1. 使用 `Ant Design Pro`
2. 使用 `Umi Max`
3. 使用 `React + TypeScript`
4. 独立于用户端工程

规则：

1. 管理端以数据管理效率优先
2. 管理端不以 SEO 为目标
3. 不要求与用户端共用组件、样式模板或脚手架
4. 安装依赖时必须在 `src/frontend/web-admin/` 内执行，或使用 `pnpm --dir "D:/project/CheapAi/src/frontend/web-admin" ...`

## 6.3 Node.js 依赖边界

规则：

1. 仓库根目录不承担 Node.js 依赖安装职责
2. 不在仓库根目录执行 `pnpm install`
3. 不在仓库根目录保留 Node.js 依赖产物
4. 具体执行规范遵守 `依赖安装规范.md`

---

## 7. 后端开发规范

## 7.1 API 风格

规则：

1. 使用 `ASP.NET Core Controllers`
2. 不使用 Minimal API 作为主风格
3. 所有对外能力通过应用服务编排

## 7.2 参数校验

正式采用：

`FluentValidation`

规则：

1. 输入校验统一在接口层或应用层完成
2. 不把复杂校验逻辑散落在 Controller 内

## 7.3 数据访问

规则：

1. 所有数据访问使用 `SqlSugar`
2. 不混用多套主 ORM

## 7.4 日志

规则：

1. 使用 `Serilog`
2. 统一输出结构化日志
3. 敏感字段脱敏

## 7.5 接口文档

正式采用：

`Swagger / OpenAPI`

规则：

1. 所有后端能力必须可通过 Swagger 浏览
2. 管理端联调默认依赖 OpenAPI

---

## 8. 数据与缓存规范

## 8.1 MySQL

1. 所有核心业务数据入 MySQL
2. 首期不拆库
3. 数据库设计以事务一致性和可维护性优先

## 8.2 Redis

1. 只存热点、缓存、锁、限流和临时状态
2. 不存必须持久化的主业务真值

---

## 9. 调度与异步任务规范

正式采用：

`Hangfire`

建议任务类型：

1. 价格抓取任务
2. 平台测试任务
3. 风险分析任务
4. 排行聚合刷新任务
5. 榜单同步任务
6. 补测任务

规则：

1. 任务必须可重试
2. 任务必须可追踪
3. 高风险任务必须支持手动补跑
4. 分布式执行时要加锁

---

## 10. 部署规范

正式采用：

`Linux + 宝塔 + Docker + Docker Compose`

首期服务建议拆为：

1. `public-web`
2. `admin-web`
3. `api`
4. `jobs`
5. `mysql`
6. `redis`

建议 Nginx / 宝塔层：

1. `www` 转发用户端
2. `admin` 转发管理端
3. `api` 转发后端 API
4. 统一 HTTPS

---

## 11. 当前阶段明确不做的内容

本技术开发规范当前明确不定义：

1. 具体 API 路由清单
2. 请求响应 JSON 字段
3. 详细数据库表字段
4. 详细权限矩阵

这些留到后续文档：

1. 功能详细设计文档
2. 数据库设计文档
3. API 设计文档
4. 自动化测试与验收规范

---

## 12. 当前结论

CheapAI 项目的正式技术基座已经确定为：

1. `.NET 10 LTS`
2. `ASP.NET Core Web API`
3. `SqlSugar`
4. `MySQL 8.4 LTS`
5. `Redis 7+`
6. `Hangfire`
7. `Next.js App Router + React + TypeScript`
8. `React + Ant Design Pro + Umi Max`
9. `Linux + 宝塔 + Docker`

一句话总结：

**后端用原生 .NET，数据访问统一用 SqlSugar，用户端用 Next.js 做 SEO，管理端用成熟的 React 后台方案，部署走 Linux + Docker。**
