## 2. 全局约定

## 2.1 前端工程边界

前端严格分为两个独立工程：

### 用户端

- 工程目录：`src/frontend/web-public`
- 服务对象：公开访客
- 目标：SEO、榜单浏览、站点详情、自助测试、公开提交流程

### 管理端

- 工程目录：`src/frontend/web-admin`
- 服务对象：管理员
- 目标：录入、维护、抓取、测试、风控、审核、文章管理

### 明确约束

1. 两端独立构建
2. 两端独立部署
3. 两端独立环境变量
4. 不建立共享前端模板
5. 不建立共享组件库
6. 不要求两端视觉代码复用
7. 两端只共享后端 API 契约事实

## 5. 后台任务流

## 5.1 价格抓取任务流

1. Hangfire 按小时调度抓取任务
2. 根据站点抓取规则选择页面抓取或接口抓取
3. 解析价格、币种、充值比例、赠送规则
4. 写入报价快照
5. 若解析失败，记录抓取失败日志
6. 若变化异常，进入人工复核队列

## 5.2 平台定时测试任务流

1. Hangfire 生成站点-模型测试任务
2. 测试服务发起真实请求
3. 记录连通性、可用性、速度和 usage
4. 写入测试记录
5. 推送到风险分析阶段

## 5.3 风险分析任务流

1. 读取新测试记录
2. 按规则分析风险
3. 写入风险证据
4. 计算风险分
5. 如果命中高风险，自动加入补测队列

## 5.4 排行聚合刷新流

1. 读取测试记录与报价快照
2. 计算 24h / 7d / 30d 聚合指标
3. 刷新模型排行快照
4. 刷新站点排行快照
5. 清理相关缓存

## 5.5 第三方榜单同步流（P2）

1. 定时读取第三方榜单源
2. 标准化模型映射
3. 写入能力榜快照

## 6. 状态流转

## 6.1 站点状态流转

`draft -> active -> suspended -> archived`

规则：

1. 新建站点默认为 `draft`
2. 完成基础资料和测试后可转 `active`
3. 长期异常或人工下线可转 `suspended`
4. 明确弃用时转 `archived`

## 6.2 提交审核流转

`pending -> approved -> converted`

或

`pending -> rejected`

## 6.3 风险复核流转

`pending_review -> confirmed`

或

`pending_review -> false_positive`

## 7. 核心算法伪代码

## 7.1 实际折算价

```pseudo
function calculateEffectivePrice(siteUnitPrice, paidAmountLocal, fxRate, usableCredit):
    paidAmountUsd = paidAmountLocal / fxRate
    costPerCreditUsd = paidAmountUsd / usableCredit
    return siteUnitPrice * costPerCreditUsd
```

## 7.2 可用性聚合

```pseudo
function calculateAvailability(records):
    total = count(records)
    success = count(records where record.success == true)
    if total == 0:
        return 0
    return success / total
```

## 7.3 稳定性评分

```pseudo
function calculateStability(records):
    availabilityRate = calculateAvailability(records)
    ftCv = std(records.firstTokenMs) / mean(records.firstTokenMs)
    rtCv = std(records.fullResponseMs) / mean(records.fullResponseMs)
    ftStability = 1 - min(ftCv, 1)
    rtStability = 1 - min(rtCv, 1)
    return 100 * (0.6 * availabilityRate + 0.2 * ftStability + 0.2 * rtStability)
```

## 7.4 速度评分

```pseudo
function calculateSpeedScore(firstTokenScore, fullResponseScore):
    return 100 * (0.6 * firstTokenScore + 0.4 * fullResponseScore)
```

## 7.5 综合性价比评分

```pseudo
function calculateValueScore(priceScore, availabilityScore, stabilityScore, speedScore, riskScore):
    safetyScore = 100 - riskScore
    return (
        0.30 * priceScore +
        0.25 * availabilityScore +
        0.20 * stabilityScore +
        0.10 * speedScore +
        0.15 * safetyScore
    )
```

## 7.6 站点整体评分

```pseudo
function calculateSiteScore(modelCoverageScore, avgPriceScore, avgAvailabilityScore, avgStabilityScore, avgSafetyScore, enterpriseScore):
    return (
        0.15 * modelCoverageScore +
        0.20 * avgPriceScore +
        0.20 * avgAvailabilityScore +
        0.20 * avgStabilityScore +
        0.15 * avgSafetyScore +
        0.10 * enterpriseScore
    )
```

## 7.7 风险分

```pseudo
function calculateRiskScore(ruleHits):
    total = 0
    for hit in ruleHits:
        total += hit.scoreDelta
    return min(total, 100)
```

## 7.8 风险命中后自动补测

function handleRiskAfterTest(testRecord, riskScore):
    if riskScore >= 51:
        createRetestJob(
            siteId = testRecord.siteId,

## 8. 失败场景与处理

## 8.1 抓取失败

处理：

1. 记录抓取日志
2. 保留上次有效报价
3. 提示后台人工复核

## 8.2 测试失败

处理：

1. 写入失败记录
2. 归类错误类型
3. 参与可用性计算
4. 可触发重试或补测

## 8.3 风险误报

处理：

1. 管理员可标记误报
2. 标记后保留证据但不按高风险前台展示
3. 进入规则调优待办

## 8.4 自助测试额度消耗

处理：

1. 提交前明确提示
2. 测试页展示“会消耗你的额度”
3. 不自动重试用户自助测试

## 8.5 第三方榜单同步失败

处理：

1. 保留最近一次成功快照
2. 前台展示“第三方数据同步延迟”

---

## 9. 当前结论

CheapAI 的功能实现必须遵守以下核心边界：

1. 用户端与管理端完全独立
2. 公共排行只使用平台定时测试数据
3. 用户自助测试只作为个人诊断工具
4. 风险判断必须可解释且可复核
5. 所有复杂判断都必须有后台任务和状态流转支撑

### 10.3 当前数据流设计

OpenRouter 模型导入流：

```pseudo
function importOpenRouterModels():
    rawModels = fetch("https://openrouter.ai/api/v1/models")
    for raw in rawModels:
        officialModelId = raw.id
        providerSlug = normalize(firstSegment(raw.id))
        requestName = lastSegment(raw.id)
        displayName = removeProviderPrefix(raw.name)
        apiType = inferApiType(providerSlug, displayName)
        provider = ensureModelProvider(providerSlug)
        upsertModel(
            providerId = provider.id,
            officialModelId = officialModelId,
            requestName = requestName,
            displayName = displayName,
            apiType = apiType,
            prices = convertOpenRouterPriceToPerMillionTokens(raw.pricing),
            capabilityScore = calculateCapabilityScore(raw)
        )
```

中转价格抓取匹配流：

```pseudo
function matchRelayPricingItem(item):
    model = findModelByRequestName(item.requestName)
    if model is null and item.officialModelId is not empty:
        model = findModelByOfficialModelId(item.officialModelId)
    if model is null:
        model = createModelFromPricingItem(item)
    return upsertRelayOffer(model.id, item)
```

首页热门模型读取流：

```pseudo
function getHomePopularModels():
    models = query active models where isHot = true order by sortOrder
    if models is empty:
        models = query active models order by sortOrder limit defaultLimit
    return models.map(toHomePopularModelResponse)
```

### 10.4 当前验收口径

1. 登录成功后应直接进入后台主页，不需要重复登录。
2. 后台菜单点击后应保持选中状态，不应卡死。
3. 中转站新增、编辑、详情应为弹窗。
4. 中转详情应有基本信息、模型信息、最近测试记录三个 Tab。
5. 模型列表应能直接设置排序和热门。
6. 用户端首页和首页测试模块应显示后台配置的热门模型。
7. OpenRouter 抓取后的模型名称不应重复携带供应商前缀。
8. OpenRouter 抓取后的模型必须有 `displayName`、`requestName`、`officialModelId`、`providerId`、`apiType`。
