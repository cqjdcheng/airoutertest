# CheapAI 部署运维与验收手册

## 1. 部署目标

CheapAI 按独立服务部署：

- `api`：ASP.NET Core Web API，默认容器端口 `8080`
- `jobs`：后台任务服务，负责抓取、测试、风险重算和排行聚合
- `public-web`：用户端 Next.js，默认容器端口 `3000`
- `admin-web`：管理端 Umi 静态站点，默认容器端口 `80`
- `mysql`：MySQL 8.4
- `redis`：Redis 7

用户端和管理端是两个完全独立的前端工程、独立构建、独立部署，不建立共享前端模板。

## 2. 必填环境变量

本地默认配置见仓库根目录 `.env.example`。

生产部署必须改动：

- `MYSQL_ROOT_PASSWORD`
- `CHEAPAI_JWT_SIGNING_KEY`
- `CHEAPAI_BOOTSTRAP_ADMIN_PASSWORD`
- `PUBLIC_API_BASE_URL`
- `ADMIN_API_BASE_URL`

真实外部验收需要额外配置：

- `CHEAPAI_REAL_RELAY_BASE_URL`
- `CHEAPAI_REAL_RELAY_API_KEY`
- `CHEAPAI_REAL_RELAY_MODEL`
- `CHEAPAI_REAL_PRICE_SOURCE_URL`，可选

真实 API Key 不允许写入仓库，只能放在服务器环境变量或本地未提交的 `.env.local`。

## 3. 本地验证命令

先分别安装各目录依赖：

```powershell
pnpm install --dir "D:/project/CheapAi/tools"
pnpm install --dir "D:/project/CheapAi/src/frontend/web-public"
pnpm install --dir "D:/project/CheapAi/src/frontend/web-admin"
```

再在 `D:/project/CheapAi` 执行：

```powershell
pnpm --dir "D:/project/CheapAi/tools" exec powershell -ExecutionPolicy Bypass -File loop/loop.ps1 -Stage p2
powershell -ExecutionPolicy Bypass -File tools/acceptance/real-env-smoke.ps1
```

`pnpm --dir "D:/project/CheapAi/tools" exec powershell -ExecutionPolicy Bypass -File loop/loop.ps1 -Stage p2` 会执行：

- 停止当前项目旧进程
- 后端 build/test
- 用户端 build
- 管理端 build
- 启动 API、用户端、管理端
- 执行 API 冒烟
- 执行后台任务冒烟
- 截图用户端和管理端页面
- 输出报告到 `artifacts/loop/<timestamp>/report.md`

`powershell -ExecutionPolicy Bypass -File tools/acceptance/real-env-smoke.ps1` 在未传入 `-RunExternal` 时只验证本地 API 和环境变量状态，不会访问真实中转站。

## 4. Docker 部署命令

服务器安装 Docker 后执行：

```bash
docker compose --env-file .env up -d --build
docker compose ps
docker compose logs -f api
docker compose logs -f jobs
```

配置检查：

```bash
docker compose --env-file .env config
```

当前本地开发机未安装 Docker，因此本地无法执行 `docker compose config`；该项需要在服务器或已安装 Docker 的环境完成。

## 5. 宝塔 / Nginx 反代建议

建议使用独立子域名：

- `www.example.com` 反代到 `public-web:3000`
- `admin.example.com` 反代到 `admin-web:80`
- `api.example.com` 反代到 `api:8080`

管理端和 API 分离后，需要确保：

- API 允许管理端域名跨域访问
- Refresh Token Cookie 在 HTTPS 下启用 `Secure`
- 生产 JWT Signing Key 使用高强度随机字符串

## 6. 发布前验收标准

必须全部通过：

- `dotnet build`
- `dotnet test`
- `pnpm --dir "D:/project/CheapAi/src/frontend/web-public" build`
- `pnpm --dir "D:/project/CheapAi/src/frontend/web-admin" build`
- `pnpm --dir "D:/project/CheapAi/tools" exec powershell -ExecutionPolicy Bypass -File loop/loop.ps1 -Stage p2`
- 用户端关键截图无明显布局问题
- 管理端关键截图可正常显示列表和操作入口
- 真实外部验收在配置真实环境变量后通过

真实外部验收命令：

```powershell
powershell -ExecutionPolicy Bypass -File tools/acceptance/real-env-smoke.ps1 -RunExternal
```

## 7. 已知限制

- 没有真实中转站 API Key 时，只能验证本地链路和保留域名链路，不能标记真实模型调用验收完成。
- 本地未安装 Docker 时，Docker Compose 只能做文件级审查，不能做容器级启动验收。
- 用户自助测试结果不进入公共排行；公共排行只使用平台定时测试和聚合快照。
