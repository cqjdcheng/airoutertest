# AI 中转比价网需求文档

## 1. 文档目标

本文档用于明确 AI 中转比价网的产品需求、核心数据模型和首期 MVP 范围，作为后续产品设计、技术方案设计和开发实施的依据。

---

## 2. 产品定位

AI 中转比价网是一个面向 AI API 使用者的中转站数据平台，核心目标不是单纯收录站点，而是帮助用户：

1. 找到价格合理、真实可用、稳定性高的 AI 中转站。
2. 对比同一模型在不同中转站的价格、可用性、速度和风险。
3. 识别中转站是否存在缓存假响应、模型偷换、降级冒充、价格虚标、响应伪造等问题。

---

## 3. 目标用户

### 3.1 个人开发者

- 关注性价比。
- 希望价格便宜且模型真实可用。

### 3.2 企业采购和部分高频开发者

- 更关注稳定性、可靠性和长期可用性。
- 对价格不敏感，但关注是否支持开票、退款、文档和持续运营能力。

### 3.3 羊毛党 / 极致低价用户

- 关注白嫖、低价模型和活动站点。
- 会更关注低价入口和便宜模型列表。

---

## 4. 核心用户场景

### 4.1 场景一：按模型找最划算的中转站

用户选择某个模型后，查看不同中转站的：

- 当前站点标价
- 实际折算价
- 可用性
- 稳定性
- 响应速度
- 风险状态

### 4.2 场景二：找稳定可用的长期站点

用户按中转站筛选：

- 支持开票
- 支持退款
- 有文档
- 站点存活时间长
- 稳定性高

### 4.3 场景三：测试某个中转站的某个模型

用户可以手动输入：

- 网站地址
- API 密钥
- 模型名称

系统发起测试并返回：

- 是否可用
- 首 token 时间
- 完整响应耗时
- 是否存在反造假风险

### 4.4 场景四：查看平台定时测试结果

用户直接查看平台对已收录中转站进行的每小时测试结果、历史记录、稳定性趋势和风险状态。

---

## 5. 产品目标

### 5.1 核心目标

- 建立可信的中转站数据索引。
- 建立统一的价格换算体系。
- 建立自动化测试和反造假能力。
- 为不同类型用户提供可筛选、可排序、可验证的决策依据。

### 5.2 短期商业化目标

- 跳转中转站时支持携带邀请链接获取返利。
- 为优质中转站提供少量广告位。

---

## 6. 产品范围

### 6.1 首期 MVP 范围

首期必须实现以下能力：

1. 中转站大全
2. 按模型的价格排行
3. 按模型的稳定性排行
4. 按模型的综合性价比排行
5. 按中转站的整体评分排行
6. 用户自助测试中转站模型
7. 平台定时测试已收录中转站模型
8. 反造假检测与展示
9. 管理后台录入、审核、抓取、测试管理
10. 模型能力排行接入第三方榜单
11. 公开提交站点入口 + 后台审核

### 6.2 后置功能

以下功能不属于首期 MVP：

- 文章系统
- 多角色后台权限
- 大规模广告系统
- 复杂会员体系

## 7. 核心数据模型

### 7.1 RelaySite（中转站）

字段建议：

- 名称
- 域名 / 站点地址
- 简介
- 付款方式
- 是否支持退款
- 是否支持开票
- 是否有官方文档
- 站点创建时间
- 平台首次收录时间
- 当前状态
- 充值币种
- 充值比例说明
- 邀请链接
- 优点
- 缺点
- 近期体验
- 内部测试账号信息（仅后台）

### 7.2 Model（模型）

字段建议：

- 模型名称
- 厂商
- 官方模型 ID
- 最后发布时间 / 更新时间
- 模型能力标签
- 官方输入价格（USD / 1M tokens）
- 官方输出价格（USD / 1M tokens）
- 第三方能力排行分数
- 第三方能力排行来源
- 第三方能力排行更新时间

### 7.3 Channel（渠道）

定义：

- 中转站内部接入的上游供应商、号池或其他接入来源。

处理方式：

- 数据模型中保留。
- 用于抓取、测试和反造假分析。
- 前台默认不展示。
- 只有存在多个渠道且差异显著时，前台详情页才可展示。

### 7.4 RelayOffer（中转站-渠道-模型关系）

字段建议：

- 中转站 ID
- 模型 ID
- 渠道 ID（可为空）
- 站点标价
- 标价币种
- 充值比例
- 赠送比例 / 活动说明
- 实际折算价（统一换算为 USD）
- 官方参考价
- 价格抓取时间
- 是否人工校验

### 7.5 TestRecord（测试记录）

字段建议：

- 测试对象类型
  - 平台定时测试
  - 用户自助测试
- 中转站
- 模型
- 渠道（如有）
- 请求时间
- 成功 / 失败
- 失败原因
- 首 token 时间
- 完整响应耗时
- 响应内容摘要
- 反造假检测结果
- 风险分
- 风险证据

### 7.6 Submission（站点提交）

字段建议：

- 提交站点名称
- 提交地址
- 联系方式（可选）
- 备注
- 提交时间
- 审核状态
- 审核结果

## 8. 价格体系

### 8.1 价格字段定义

平台至少保留三类价格：

1. 官方价
2. 站点标价
3. 实际折算价

### 8.2 展示规则

- 前台主展示价格：站点标价
- 前台主比价字段：实际折算价
- 前台参考价格：官方价

### 8.3 实际折算价规则

实际折算价统一换算为 USD，计算时需要考虑：

- 标价币种
- 汇率
- 充值比例
- 赠送金额
- 活动赠送

建议公式：

`实际折算价 = 用户实际支付成本 / 实际可用额度`

如中转站存在“充 100 送 20”，则应按实际可用额度重新折算，而不是直接按面值价格参与排行。

## 9. 测试与评估体系

### 9.1 测试方式

平台存在两类测试：

1. 用户自助测试
2. 平台定时测试

### 9.2 用户自助测试

用户输入：

- 网站地址
- API 密钥
- 模型名称

系统输出：

- 是否可用
- 首 token 时间
- 完整响应耗时
- 风险状态
- 风险分
- 检测证据摘要

建议约束：

- 密钥不得明文落库。
- 密钥仅用于当前测试任务。
- 日志中不得记录明文密钥。
- 需要频控和基础防滥用机制。

### 9.3 平台定时测试

- 对已收录中转站模型进行每小时测试。
- 测试结果写入数据库，用于生成历史记录和稳定性统计。

### 9.4 指标定义

#### 可用性

- 一定时间窗口内成功请求数 / 总请求数。

#### 稳定性

- 一定时间窗口内成功率波动小、响应耗时波动小。
- 建议至少按以下窗口统计：
  - 24 小时
  - 7 天
  - 30 天

#### 速度

- 首 token 时间
- 完整响应耗时

---

## 10. 反造假体系

### 10.1 识别目标

首期需要识别以下风险：

1. 缓存假响应
2. 模型偷换
3. 降级模型冒充高阶模型
4. 价格虚标
5. 响应伪造

### 10.2 结果展示方式

反造假结果采用三层结构：

1. 状态标签
2. 风险分
3. 证据记录

### 10.3 展示规则

- 列表页展示：
  - 状态标签
  - 风险分
- 详情页展示：
  - 完整证据记录
  - 命中的风险类型
  - 最近一次检测时间

### 10.4 风险分建议

建议风险分取值范围为 `0-100`：

- `0-20`：低风险
- `21-50`：中风险
- `51-80`：高风险
- `81-100`：严重可疑

首期规则建议做成可配置，不要硬编码在业务逻辑里。

## 11. 模型能力排行

### 11.1 数据来源选择

截至 2026-05-10，建议：

- 主来源使用 `Artificial Analysis Intelligence Index`
- 辅助参考使用 `LMArena`

### 11.2 选择理由

选择 `Artificial Analysis` 作为主来源的原因：

1. 官方公开方法论较完整。
2. 是综合性能力指数，不是单一主观投票。
3. 覆盖推理、知识、数学、编程等多个维度。
4. 更适合做站内“模型能力排行”的统一口径。

`LMArena` 适合作为补充参考，因为它反映真实用户偏好，但更偏主观对战，不适合作为站内唯一能力主榜。

### 11.3 展示方式

- 模型详情页显示第三方能力分数。
- 能力排行榜页面单独展示榜单来源、更新时间和跳转链接。
- 页面需明确标注“该榜单来源于第三方，不代表本站自测结论”。

参考来源：

- Artificial Analysis 方法论：https://artificialanalysis.ai/methodology/intelligence-benchmarking
- Artificial Analysis 首页：https://artificialanalysis.ai/
- LMArena 排行政策：https://arena.ai/blog/policy/

## 12. 排行榜设计

### 12.1 主榜单

首期至少提供以下四类主榜：

1. 按模型看最便宜站点
2. 按模型看最稳定站点
3. 按模型看综合性价比
4. 按中转站看整体评分

### 12.2 价格榜

排序字段：

- 主排序：实际折算价升序
- 次排序：可用性降序

### 12.3 稳定性榜

排序字段：

- 主排序：7 天稳定性得分降序
- 次排序：24 小时可用性降序

### 12.4 综合性价比榜

建议按以下因素计算：

- 实际折算价
- 可用性
- 稳定性
- 首 token 时间
- 完整响应耗时
- 风险分

建议首期采用可配置权重模型，不写死公式。

### 12.5 中转站整体评分榜

建议综合：

- 覆盖模型数量
- 平均价格竞争力
- 平均可用性
- 平均稳定性
- 平均风险分
- 是否支持退款 / 开票 / 文档
- 存活时长

## 17. 非功能要求

### 17.1 安全性

- 用户输入的 API 密钥不得明文落库。
- 敏感信息在日志中必须脱敏。
- 后台测试账号仅管理员可见。

### 17.2 可信性

- 所有测试结果应记录时间和来源。
- 第三方榜单必须标注来源和更新时间。
- 排行榜应说明计算口径。

### 17.3 可维护性

- 评分规则、风险规则、价格换算规则建议可配置。
- 抓取规则和测试规则应支持后续扩展。

---

## 18. 首期建议方案

以下内容当前未被用户逐条确认，但建议直接纳入首期设计：

1. 用户自助测试密钥仅临时使用，不持久化保存。
2. 稳定性默认提供 24 小时、7 天、30 天三个窗口。
3. 综合评分和风险分规则全部做成可配置。
4. 站点详情页展示历史价格趋势和历史稳定性趋势。
5. “站点存活时间长”优先按站点创建时间展示，同时保留平台首次收录时间作为辅助字段。

---

## 19. 当前结论

该项目首期本质上是一个以“中转站收录 + 统一比价 + 自动化测试 + 反造假”为核心的 AI 数据平台。

优先级排序建议如下：

1. 数据可信
2. 价格可比
3. 可用性与稳定性可验证
4. 风险可解释
5. 排行和商业化在以上能力之上构建
