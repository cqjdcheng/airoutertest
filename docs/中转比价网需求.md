### 1.1 问卷依据与调整原则

本文档已结合 2026-05-11 的问卷统计结果进行校准。本次问卷有效填写量为 27，样本主要来自个人开发者 / 上班族，占比 85.2%。因此本次调整优先服务个人开发者、高频 API 使用者和低价敏感用户，不把企业采购场景作为首期主路径。

关键调研结论：

1. 用户最看重的是模型真实可用、实际折算后价格、长期稳定性、成功率和响应速度。
2. 用户最常遇到的问题是标价便宜但实际不便宜、模型疑似偷换、成功率不稳定、模型疑似降级。
3. 用户最想使用的功能是按模型查看最便宜站点、最稳定站点、综合性价比排行和中转站整体评分。
4. 首期最值得优先做好的能力是模型稳定性排行、模型价格排行、风险识别 / 反造假和综合性价比排行。
5. 用户自助测试存在使用意愿，但核心顾虑是 API 密钥安全和测试结果可信，因此不应阻塞首期核心排行上线。
6. 第三方模型能力排行、公开提交站点、企业筛选属于低优先级能力，应后置。

调整原则：

1. 首期从“功能覆盖完整”调整为“可信排行先跑通”。
2. 排行和详情必须展示数据来源、更新时间、测试口径和关键证据。
3. 平台定时测试数据用于公共排行，用户自助测试仅作为用户个人诊断工具。

## 2. 产品定位

AI 中转比价网是一个面向 AI API 使用者的中转站数据平台，核心目标不是单纯收录站点，而是帮助用户：

1. 找到价格合理、真实可用、稳定性高的 AI 中转站。
2. 对比同一模型在不同中转站的价格、可用性、速度和风险。
3. 识别中转站是否存在缓存假响应、模型偷换、降级冒充、价格虚标、响应伪造等问题。

## 3. 目标用户

### 3.1 首期核心用户：个人开发者 / 高频 API 使用者

- 占本次问卷样本 85.2%，是首期最明确的目标用户。
- 关注模型真实可用、实际折算价、长期稳定性、成功率和响应速度。
- 典型诉求是找到便宜、稳定、可替代当前站点的中转站。

### 3.2 次级用户：羊毛党 / 低价导向用户

- 关注白嫖、低价模型和活动站点。
- 会重点使用价格榜和低价模型列表。
- 需要避免平台被纯低价导向带偏，低价必须和可用性、风险分一起展示。

### 3.3 后置用户：企业采购 / 企业技术负责人

- 本次样本占比仅 7.4%，不能作为首期需求优先级的主要依据。
- 企业相关字段仍需保留，包括开票、退款、文档、站点存活时间和客服响应。
- 首期前台可以弱化企业筛选，后续根据企业样本补充调研后再增强。

## 4. 核心用户场景

### 4.1 场景一：按模型找最划算的中转站

用户选择某个模型后，查看不同中转站的：

- 当前站点标价
- 实际折算价
- 可用性
- 稳定性
- 响应速度
- 风险状态

### 4.2 场景二：按模型找最稳定的备用站

用户已有常用中转站，但在当前站点不可用、速度慢或疑似降级时，需要快速找到备用站点。用户选择某个模型后，查看不同中转站的：

- 24 小时可用性
- 7 天稳定性
- 首 token 时间
- 完整响应耗时
- 最近一次测试结果
- 风险状态

### 4.3 场景三：识别模型偷换和降级风险

用户在准备充值或遇到异常体验时，希望判断中转站是否存在：

- 模型偷换
- 降级模型冒充高阶模型
- 上游 / 号池不稳定
- 价格虚标
- 响应伪造

### 4.4 场景四：测试某个中转站的某个模型

用户可以手动输入：

- 网站地址
- API 密钥
- 模型名称

系统发起测试并返回：

- 是否可用
- 首 token 时间
- 完整响应耗时
- 是否存在反造假风险
- 测试会消耗用户额度的明确提示
- API 密钥不会落库的安全说明

### 4.5 场景五：查看平台定时测试结果

用户直接查看平台对已收录中转站进行的每小时测试结果、历史记录、稳定性趋势和风险状态。

### 4.6 场景六：企业条件筛选

企业采购或团队用户可以按以下条件筛选站点：

- 支持开票
- 支持退款
- 有文档
- 站点存活时间长
- 稳定性高

该场景保留字段和基础筛选能力，但不是首期首页和排行页的主路径。

## 5. 产品目标

### 5.1 核心目标

- 建立可信的中转站数据索引。
- 建立统一的价格换算体系。
- 建立自动化测试和反造假能力。
- 为不同类型用户提供可筛选、可排序、可验证的决策依据。

### 5.2 短期商业化目标

- 跳转中转站时支持携带邀请链接获取返利。
- 为优质中转站提供少量广告位。

## 6. 产品范围

### 6.1 P0 MVP 范围

首期必须先跑通可信排行闭环：

1. 中转站基础收录和后台维护。
2. 模型维度价格排行，主排序使用实际折算价。
3. 模型维度稳定性排行，至少展示 24 小时可用性、7 天稳定性、首 token 时间和完整响应耗时。
4. 平台定时测试已收录中转站模型，公共排行只使用平台统一测试口径。
5. 基础反造假检测与展示，优先覆盖模型偷换、降级模型冒充高阶模型、上游 / 号池不稳定、价格虚标。
6. 精简站点详情页，展示价格、稳定性、最近测试结果、风险证据摘要和跳转链接。
7. 管理后台录入、价格抓取、测试管理、风险查看和人工复核。
8. 排行口径说明，包括数据更新时间、测试来源、价格折算规则和风险分规则。

### 6.2 P1 增强范围

以下能力建议在 P0 跑通后再做：

1. 按模型的综合性价比排行。
2. 按中转站的整体评分排行。
3. 历史价格变化趋势和历史稳定性趋势。
4. 用户自助测试中转站模型，但必须先完成 Key 安全、日志脱敏、额度消耗提示和频控。
5. 风险证据详情页和误报复核流程。

### 6.3 后置功能

以下功能不属于首期 MVP：

- 第三方模型能力排行独立页
- 公开提交站点入口 + 后台审核
- 企业筛选增强
- 文章系统
- 多角色后台权限
- 大规模广告系统
- 复杂会员体系

## 7. 核心数据模型

### 7.1 RelaySite（中转站）

字段建议：

- 名称
- 域名 / 站点地址
- 简介
- 付款方式
- 是否支持退款
- 是否支持开票
- 是否有官方文档
- 站点创建时间
- 平台首次收录时间
- 当前状态
- 充值币种
- 充值比例说明
- 邀请链接
- 优点
- 缺点
- 近期体验
- 内部测试账号信息（仅后台）

### 7.2 Model（模型）

字段建议：

- 模型名称
- 厂商
- 官方模型 ID
- 最后发布时间 / 更新时间
- 模型能力标签
- 官方输入价格（USD / 1M tokens）
- 官方输出价格（USD / 1M tokens）
- 第三方能力排行分数
- 第三方能力排行来源
- 第三方能力排行更新时间

### 7.3 Channel（渠道）

定义：

- 中转站内部接入的上游供应商、号池或其他接入来源。

处理方式：

- 数据模型中保留。
- 用于抓取、测试和反造假分析。
- 前台默认不展示。
- 只有存在多个渠道且差异显著时，前台详情页才可展示。

### 7.4 RelayOffer（中转站-渠道-模型关系）

字段建议：

- 中转站 ID
- 模型 ID
- 渠道 ID（可为空）
- 站点标价
- 标价币种
- 充值比例
- 赠送比例 / 活动说明
- 实际折算价（统一换算为 USD）
- 官方参考价
- 价格抓取时间
- 是否人工校验

### 7.5 TestRecord（测试记录）

字段建议：

- 测试对象类型
  - 平台定时测试
  - 用户自助测试
- 中转站
- 模型
- 渠道（如有）
- 请求时间
- 成功 / 失败
- 失败原因
- 首 token 时间
- 完整响应耗时
- 响应内容摘要
- 反造假检测结果
- 风险分
- 风险证据

### 7.6 Submission（站点提交）

公开提交站点入口已根据问卷结果后置到 P2，但数据模型可以提前预留，便于后续接入审核流。

字段建议：

- 提交站点名称
- 提交地址
- 联系方式（可选）
- 备注
- 提交时间
- 审核状态
- 审核结果

## 8. 价格体系

### 8.1 价格字段定义

平台至少保留三类价格：

1. 官方价
2. 站点标价
3. 实际折算价

### 8.2 展示规则

- 前台主展示价格：站点标价
- 前台主比价字段：实际折算价
- 前台参考价格：官方价

### 8.3 实际折算价规则

实际折算价统一换算为 USD，计算时需要考虑：

- 标价币种
- 汇率
- 充值比例
- 赠送金额
- 活动赠送

建议公式：

`实际折算价 = 用户实际支付成本 / 实际可用额度`

如中转站存在“充 100 送 20”，则应按实际可用额度重新折算，而不是直接按面值价格参与排行。

## 9. 测试与评估体系

### 9.1 测试方式

平台存在两类测试：

1. 用户自助测试
2. 平台定时测试

### 9.2 用户自助测试

根据问卷结果，自助测试有使用意愿，但优先级低于价格排行、稳定性排行和风险识别。该能力建议作为 P1 诊断工具实现，不阻塞 P0 上线。

用户输入：

- 网站地址
- API 密钥
- 模型名称

系统输出：

- 是否可用
- 首 token 时间
- 完整响应耗时
- 风险状态
- 风险分
- 检测证据摘要

建议约束：

- 密钥不得明文落库。
- 密钥仅用于当前测试任务。
- 日志中不得记录明文密钥。
- 需要频控和基础防滥用机制。
- 页面必须提示测试会消耗用户 API 额度。
- 建议引导用户使用临时 Key 或低额度 Key。
- 自助测试结果默认只对当前用户可见，不进入公共排行。

### 9.3 平台定时测试

- 对已收录中转站模型进行每小时测试。
- 测试结果写入数据库，用于生成历史记录和稳定性统计。

### 9.4 指标定义

#### 可用性

- 一定时间窗口内成功请求数 / 总请求数。

#### 稳定性

- 一定时间窗口内成功率波动小、响应耗时波动小。
- 建议至少按以下窗口统计：
  - 24 小时
  - 7 天
  - 30 天

#### 速度

- 首 token 时间
- 完整响应耗时

## 10. 反造假体系

### 10.1 识别目标

首期反造假应服务于“模型真实可用”这个核心需求。根据问卷结果，优先级从高到低建议为：

1. 降级模型冒充高阶模型
2. 模型偷换
3. 缓存假响应
4. 上游 / 号池不稳定
5. 价格虚标
6. 响应伪造

首期 P0 至少覆盖模型偷换、降级模型冒充高阶模型、上游 / 号池不稳定和价格虚标；缓存假响应和响应伪造可按规则成熟度逐步增强。

### 10.2 结果展示方式

反造假结果采用三层结构：

1. 状态标签
2. 风险分
3. 证据记录

### 10.3 展示规则

- 列表页展示：
  - 状态标签
  - 风险分
- 详情页展示：
  - 完整证据记录
  - 命中的风险类型
  - 最近一次检测时间

### 10.4 风险分建议

建议风险分取值范围为 `0-100`：

- `0-20`：低风险
- `21-50`：中风险
- `51-80`：高风险
- `81-100`：严重可疑

首期规则建议做成可配置，不要硬编码在业务逻辑里。

## 11. 模型能力排行

根据问卷结果，第三方模型能力排行的功能选择率为 18.5%，优先做好该能力的选择率为 3.7%。因此该能力不进入 P0 MVP，可作为 P2 独立页面或模型详情页的补充信息。

### 11.1 数据来源选择

截至 2026-05-10，建议：

- 主来源使用 `Artificial Analysis Intelligence Index`
- 辅助参考使用 `LMArena`

### 11.2 选择理由

选择 `Artificial Analysis` 作为主来源的原因：

1. 官方公开方法论较完整。
2. 是综合性能力指数，不是单一主观投票。
3. 覆盖推理、知识、数学、编程等多个维度。
4. 更适合做站内“模型能力排行”的统一口径。

`LMArena` 适合作为补充参考，因为它反映真实用户偏好，但更偏主观对战，不适合作为站内唯一能力主榜。

### 11.3 展示方式

- 模型详情页显示第三方能力分数。
- 能力排行榜页面单独展示榜单来源、更新时间和跳转链接。
- 页面需明确标注“该榜单来源于第三方，不代表本站自测结论”。

参考来源：

- Artificial Analysis 方法论：https://artificialanalysis.ai/methodology/intelligence-benchmarking
- Artificial Analysis 首页：https://artificialanalysis.ai/
- LMArena 排行政策：https://arena.ai/blog/policy/

## 12. 排行榜设计

### 12.1 主榜单

首期榜单优先按问卷结果调整为模型维度优先：

1. P0：按模型看最稳定站点。
2. P0：按模型看最便宜站点。
3. P0：按模型看风险较低站点或在排行中展示风险过滤。
4. P1：按模型看综合性价比。
5. P1：按中转站看整体评分。

### 12.2 价格榜

排序字段：

- 主排序：实际折算价升序
- 次排序：可用性降序

### 12.3 稳定性榜

排序字段：

- 主排序：7 天稳定性得分降序
- 次排序：24 小时可用性降序

### 12.4 综合性价比榜

建议按以下因素计算：

- 实际折算价
- 可用性
- 稳定性
- 首 token 时间
- 完整响应耗时
- 风险分

建议首期采用可配置权重模型，不写死公式。

### 12.5 中转站整体评分榜

建议综合：

- 覆盖模型数量
- 平均价格竞争力
- 平均可用性
- 平均稳定性
- 平均风险分
- 是否支持退款 / 开票 / 文档
- 存活时长

## 13. 前台功能需求

### 13.1 中转站大全

中转站大全不作为首期第一入口，应作为排行和详情之外的辅助浏览入口。

支持：

- 列表浏览
- 搜索
- 多条件筛选
- 排序
- 查看详情

### 13.2 模型价格排行页

P0 必须实现。

支持：

- 选择模型
- 查看不同站点价格对比
- 查看官方价、站点标价、实际折算价
- 查看最近测试结果

### 13.3 稳定性 / 性价比 / 整体评分排行页

其中稳定性排行为 P0，综合性价比排行和整体评分排行为 P1。

支持：

- 统一排序和筛选
- 按模型或站点切换视角
- 查看历史趋势入口

### 13.4 模型能力排行页

该页面后置到 P2，不进入 P0。

支持：

- 展示第三方能力榜单
- 标注来源
- 标注更新时间
- 跳转原始来源

### 13.5 站点详情页

站点详情页在 P0 做精简版，定位为排行结果的证据承接页，而不是完整内容型页面。至少展示：

- 站点基础信息
- 是否支持退款
- 是否支持开票
- 是否有文档
- 站点存活时间
- 支持模型列表
- 当前价格信息
- 最近测试结果
- 历史稳定性趋势
- 风险状态
- 风险分
- 风险证据摘要
- 跳转链接 / 邀请链接

建议补充展示：

- 历史价格变化趋势
- 近期体验总结

### 13.6 用户自助测试页

## 17. 非功能要求

### 17.1 安全性

- 用户输入的 API 密钥不得明文落库。
- 敏感信息在日志中必须脱敏。
- 后台测试账号仅管理员可见。

### 17.2 可信性

- 所有测试结果应记录时间和来源。
- 第三方榜单必须标注来源和更新时间。
- 排行榜应说明计算口径。

### 17.3 可维护性

- 评分规则、风险规则、价格换算规则建议可配置。
- 抓取规则和测试规则应支持后续扩展。

## 18. 首期建议方案

结合问卷结果，首期建议按以下方式收敛：

1. 首页和排行页优先围绕模型稳定性排行、模型价格排行和风险状态展开。
2. 稳定性默认先提供 24 小时和 7 天窗口，30 天窗口待数据积累后展示。
3. 价格榜必须使用实际折算价，不允许只用站点标价排序。
4. 风险检测优先覆盖模型偷换、降级模型冒充高阶模型、上游 / 号池不稳定和价格虚标。
5. 综合评分和风险分规则全部做成可配置。
6. 站点详情页 P0 做精简证据页，历史趋势和近期体验总结进入 P1。
7. 用户自助测试进入 P1，密钥仅临时使用，不持久化保存，并必须提供额度消耗提示。
8. 第三方模型能力排行、公开提交站点和企业筛选增强进入 P2。

---

## 19. 当前结论

该项目首期本质上是一个以“中转站收录 + 统一比价 + 自动化测试 + 反造假”为核心的 AI 数据平台。

调整后的优先级排序建议如下：

1. 稳定性和可用性可验证
2. 价格真实可比
3. 模型真实可用且风险可解释
4. 排行口径透明
5. 自助测试、模型能力榜、公开提交和商业化在以上能力之上构建
