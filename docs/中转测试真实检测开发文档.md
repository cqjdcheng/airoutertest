# 中转测试真实检测开发文档

## 目标

中转测试模块用于让用户输入 OpenAI 兼容接口地址、API Key、模型名称后，发起一次真实请求，并在页面立即返回检测结果。首页和自助测试页共用同一个用户端组件，但不与管理端共享任何前端模板。

## 页面功能

### 输入项

- `API 接口地址`：必填，允许输入 `https://xxx/v1` 或完整 `https://xxx/v1/chat/completions`。
- `API Key`：必填，前端 password 输入，后端只用于本次请求，不落库。
- `目标模型`：提供默认模型快捷选择。
- `自定义模型名称`：允许输入站点自定义模型名，优先级高于快捷模型。
- `测试模式`：默认 `综合检测`，覆盖知识问答、型号特征、协议一致性、响应结构和速度。
- `流式测速`：默认开启，用于测首 token 时间。
- `人机验证`：测试前必须完成服务端签发的简单挑战，降低接口被刷风险。

### 默认模型

- `gpt-5.5`
- `gpt-5.4`
- `claude-code-4.7`
- `claude-code-4.6`
- `gemini-3.1-pro`

### 页面结果

点击“开始检测”后，页面不跳转，直接展示当前检测结果：

- 综合匹配分
- 模型真实性
- Token 消耗真实性
- 响应时间
- 知识问答校验
- 型号特征校验
- 协议一致性
- 响应结构
- 检测时间
- 检测站点
- 首 token 时间
- 完整响应时间
- 输入 token、输出 token、总 token
- 风险分、风险等级、结果摘要

## 后端接口

### 获取人机验证挑战

`GET /api/v1/public/self-tests/challenge`

响应：

```json
{
  "id": "uuid",
  "question": "7 + 5 = ?",
  "expiresAt": "2026-05-12T15:00:00Z"
}
```

### 创建中转测试

`POST /api/v1/public/self-tests`

请求：

```json
{
  "siteUrl": "https://relay.example.com/v1",
  "modelName": "gpt-5.5",
  "apiKey": "sk-...",
  "isStream": true,
  "testMode": "comprehensive",
  "challengeId": "uuid",
  "challengeAnswer": "12"
}
```

响应使用现有 `ApiEnvelope<SelfTestResponse>`，扩展 `SelfTestResponse` 字段。

## 人机验证方案

首期使用服务端签发的算术挑战：

- 挑战有效期 5 分钟。
- 单次挑战只能使用一次。
- 挑战答案只存哈希，不记录明文。
- 验证失败直接拒绝创建测试。
- 后续可替换为 Cloudflare Turnstile / hCaptcha，不影响业务接口形态。

## 真实检测方案

## 探针体系评估与采用结论

用户提供的 D1-D13 / S1-S5 方案可以作为 CheapAI 中转测试的正式探针分类体系使用，但不能全部在首期以同等权重进入“模型真实性 / 是否造假”的最终判断。原因是不同探针的证据强度差异很大：协议、结构、速度、流完整性属于高置信技术证据；身份、思维链、上游指纹、提示词泄露属于低置信或高误报证据，只能作为风险证据记录，不能单独判定造假。

### 探针采用分层

| 层级 | 探针 | 采用结论 | 说明 |
| --- | --- | --- | --- |
| P0 必须实现 | D1 协议连通性 | 直接采用 | 判断接口是否可请求、鉴权是否通过、HTTP 状态是否正常。 |
| P0 必须实现 | D2 响应结构 | 直接采用 | 判断是否符合 OpenAI Chat Completions / SSE 基础结构。 |
| P0 必须实现 | D4 知识能力 | 直接采用 | 用低成本确定性题检测明显降级或假响应。 |
| P0 必须实现 | D5 内容完整性 | 直接采用 | 检查响应是否截断、空内容、非预期格式或缺字段。 |
| P0 必须实现 | D7 结构化输出 | 直接采用 | 要求返回严格 JSON，用于验证指令遵循和解析可靠性。 |
| P0 必须实现 | D8 响应时延 | 直接采用 | 记录首 token 时间、完整响应耗时和 tokens/s。 |
| P0 必须实现 | S5 流完整性 | 直接采用 | 对 stream 模式检查 SSE 事件连续性、结束标记和异常断流。 |
| P1 增强实现 | D3 身份一致性 | 低置信采用 | 模型自称身份不可靠，只能作为辅助证据。 |
| P1 增强实现 | D6 上游指纹 | 低置信采用 | 可记录 header、错误结构、响应节奏等指纹，但不能公开暴露敏感细节。 |
| P1 增强实现 | D9 性能稳定性 | 延迟采用 | 需要多次测试和时间窗口，不能通过单次自助测试判断。 |
| P1 增强实现 | D11 隐式身份验真 | 低置信采用 | 可用模型族行为特征题，但只能输出“疑似匹配 / 疑似不匹配”。 |
| P1 增强实现 | D12 推理降级检测 | 低置信采用 | 用多步推理结果检测降级，不要求模型输出思维链。 |
| P1 增强实现 | S1 Token 注入 | 辅助采用 | 检查 prompt token 明显异常、站点是否注入隐藏提示词。 |
| P1 增强实现 | S2 提示词泄露 | 受控采用 | 只用安全探针检测是否泄露测试上下文，不诱导泄露真实系统提示词。 |
| P1 增强实现 | S3 指令覆盖 | 受控采用 | 检查站点是否强行覆盖用户指令，例如强制广告、固定模板。 |
| P1 增强实现 | S4 错误响应泄露 | 受控采用 | 检查错误信息是否泄露上游、密钥片段、内部路径或堆栈。 |
| P2 后续增强 | D10 思维链特征 | 改名采用 | 不要求输出隐藏思维链，改为“推理行为特征”，只检查结论、步骤摘要和一致性。 |
| P2 后续增强 | D13 多模态能力 | 后续采用 | 需要图片 / 文件输入能力和不同模型族测试集，首期不阻塞文本模型测试。 |

| --- | --- | --- | --- | --- |

| D3 | 身份一致性 | 身份 | 是 | 记录模型自称身份；缺失或不匹配会低权重扣分。 |
| D4 | 知识能力 | 能力 | 是 | 检测明显错误、缓存假响应和低阶模型冒充。 |
| D5 | 内容完整性 | 完整性 | 是 | 检查空响应、截断、字段缺失和非预期输出。 |
| D6 | 上游指纹 | 信息 | 否 | 记录错误结构、header、响应节奏等内部证据。 |
| D7 | 结构化输出 | 能力 | 是 | 检查 JSON 输出、schema 遵循和解析成功率。 |
| D8 | 响应时延 | 性能 | 是 | 记录首 token、总耗时和 tokens/s。 |

### 使用规则

- 每个探针必须输出 `code`、`name`、`category`、`status`、`confidence`、`scoreImpact`、`riskImpact`、`evidence`。
- `status` 只允许 `pass`、`warn`、`fail`、`unknown`。
- `confidence` 只允许 `high`、`medium`、`low`。
- 公开页面默认展示摘要：可信分、风险分、关键失败项和少量证据。
- `D1`、`D3`、`S1` 等编码仅作为内部排查标识，不直接作为前台卡片标题；用户侧展示顺序号、探针名称、分类、状态、置信度和扣分。
- 管理端展示完整证据：探针明细、请求时间、错误类型、token 统计和脱敏后的诊断信息。
- 单次自助测试不得直接给出“确认造假”结论，只能给出“正常 / 可疑 / 失败 / 未知”。
- 平台定时测试可以基于多次命中、时间窗口和人工复核给出更高置信的风险结论。
- D10 不以“思维链泄露”为目标，不要求模型输出隐藏推理过程，避免把模型安全拒答误判为能力不足。

### 请求方式

对用户填写的接口发起 OpenAI Chat Completions 兼容请求：

- endpoint 自动归一化到 `/v1/chat/completions`。
- 使用用户 API Key 的 Bearer 鉴权。
- 请求 timeout 20 秒。
- 默认 `stream=true`，用于记录首 token 时间。

Claude / Anthropic 模型使用 Claude Code 兼容探测：

- endpoint 自动归一化到 `/v1/messages`。
- 请求体使用 Anthropic Messages 结构，`messages[].content` 和 `system` 都使用 `type=text` 内容块。
- 请求体带 `metadata.user_id=cheapai-self-test`，用于模拟 Claude Code / CLI 一次会话来源。
- 请求头同时带 `x-api-key` 和 `Authorization: Bearer <key>`，兼容不同中转实现。
- 请求头带 `anthropic-version: 2023-06-01`、`anthropic-beta: claude-code-20250219`、`x-claude-code-session-id: cheapai-self-test`、`x-claude-code-client: cheapai`、`User-Agent: claude-code/1.0`。
- 该模式用于发现“网页/CLI 可用但普通 API 不支持”的 Claude 满血中转，不代表最终确认真伪，仍按探针扣分和证据汇总判断。

### 探测 Prompt

一次请求内发送结构化探测：

```text
You are being tested by CheapAI. Return strict JSON only:
{
  "model_claim": "<your model identity>",
  "knowledge_answer": "<answer: 9.11 or 9.8, which is larger?>",
  "protocol_ack": "openai-chat-completions-compatible",
  "short_answer": "OK"
}
```

### 检测项

- 知识问答校验：检查常见低成本问题是否回答正确，例如 `9.8 > 9.11`。
- 型号特征校验：响应中是否出现目标模型族相关特征；强制精确识别较难，首期以可疑/通过/未知记录。
- 协议一致性：响应是否符合 OpenAI Chat Completions 或 SSE delta 结构。
- 响应结构：是否有 `choices`、`message/content` 或 `delta/content`。
- Token 消耗真实性：读取 `usage.prompt_tokens`、`usage.completion_tokens`、`usage.total_tokens`；若缺失则标记未知。若总 token 明显超过预计 1000 token，记录风险。
- 响应时间：记录首 token 和完整响应耗时。

## 评分规则

总分 `0-100`，前台显示为可信分。评分采用扣分制：先给 100 分，再按探针证据扣分，避免“接口通了就是满分”。

- `pass`：不扣分。
- `warn`：按该探针的 `riskImpact` 扣分；没有显式 `riskImpact` 时按置信度兜底扣分，高置信 18 分、中置信 10 分、低置信 4 分。
- `fail`：按该探针的 `riskImpact` 扣分；没有显式 `riskImpact` 时按置信度兜底扣分，高置信 40 分、中置信 25 分、低置信 12 分。
- `unknown`：默认仅参考；如果该未知项本身会降低可信度，则配置小额 `riskImpact` 后扣分。
- 风险分等于本次总扣分，可信分等于 `100 - 风险分`，最终都限制在 `0-100`。

首期显式扣分口径：

| 探针 | 场景 | 扣分 |
| --- | --- | --- |
| 协议连通性 | URL 无效 / 缺 API Key / 请求异常 / 超时 / 非 2xx | 18-55 |
| 响应结构 | 非 OpenAI / Anthropic 目标协议结构 | 35 |
| 内容完整性 | 空响应 / 过短响应 | 8-25 |
| 结构化输出 | 未按要求返回可解析 JSON | 22 |
| 知识能力 | 明确答错 / 不明确 | 8-30 |
| 响应时延 | 未测到首 token / 偏慢 / 明显偏慢 | 8-20 |
| Token 用量 | usage 缺失 / total_tokens 明显超过预估 | 4-18 |
| 身份一致性 | 自述缺失 / 目标族无法判断 / 自述不匹配 | 6-8 |
| 满血模型指纹 | 返回模型不一致 / 只能依赖自述身份 | 6-28 |
| 流完整性 | 流式响应结束信号不完整 | 12 |

风险等级按总扣分划分：

- `0-14`：低风险。
- `15-44`：中风险。
- `45-100`：高风险。

关键失败项：

- HTTP 401/403：中风险，提示 Key、权限或余额问题。
- 私网 / 本地地址：高风险并阻断。
- 响应非 JSON / 非 SSE：高风险。
- Token 超量明显异常：中风险。

## 数据记录

`self_tests` 表需要记录：

- 站点地址、模型名、测试模式、是否流式
- 状态、风险分、风险等级、摘要
- 首 token、完整响应时间
- 输入 token、输出 token、总 token
- 预计 token
- 可信分
- 知识问答、型号特征、协议一致性、响应结构、Token 消耗、响应时间等检查结果
- 检测详情 JSON
- 创建时间和过期时间

站点详情页的最近测试记录默认返回最近 100 条，前端只做本页内分页展示，避免只看到最近 10 条导致历史判断不足。

禁止记录：

- API Key 明文
- 完整模型响应原文
- 用户敏感请求体

## 验收标准

- 首页 API 地址和 API Key 必须可输入。
- 点击开始检测必须先完成人机验证。
- 测试结果必须在当前页面展示，不依赖跳转。
- 自定义模型名必须透传到后端。
- 后端必须真实请求用户填写的 OpenAI 兼容接口。
- 无外部真实 Key 时，使用保留域名或错误 Key 应返回明确失败结果，而不是页面崩溃。
- `/loop` 必须通过。
- MCP 必须验证输入、挑战、按钮、结果展示和截图。
