# CheapAI 依赖安装规范

## 1. 目标

约束 CheapAI 的 Node.js 依赖安装位置，避免把不同工程的包、锁文件和 `node_modules` 混装到仓库根目录，导致职责混乱、依赖漂移和工具链不可维护。

---

## 2. 总原则

所有包和依赖必须安装到各自所属工程目录，不允许安装到仓库根目录。

当前适用范围：

1. `src/frontend/web-public/`
2. `src/frontend/web-admin/`
3. `tools/`

---

## 3. 安装规则

### 3.1 用户端依赖

用户端相关依赖只允许安装在：

`src/frontend/web-public/`

例如：

1. `next`
2. `react`
3. `@tanstack/react-query`
4. `tailwindcss`
5. `typescript`

安装方式：

```powershell
pnpm install --dir "D:/project/CheapAi/src/frontend/web-public"
```

### 3.2 管理端依赖

管理端相关依赖只允许安装在：

`src/frontend/web-admin/`

例如：

1. `@umijs/max`
2. `antd`
3. `@ant-design/pro-components`
4. `typescript`

安装方式：

```powershell
pnpm install --dir "D:/project/CheapAi/src/frontend/web-admin"
```

### 3.3 工具脚本依赖

开发和验收脚本使用的 Node.js 依赖只允许安装在：

`tools/`

例如：

1. `playwright`

安装方式：

```powershell
pnpm install --dir "D:/project/CheapAi/tools"
```

---

## 4. 明确禁止

以下行为一律禁止：

1. 在仓库根目录创建前端工程依赖用 `package.json`
2. 在仓库根目录执行 `pnpm install`
3. 在仓库根目录保留 Node.js 依赖产生的 `node_modules`
4. 把用户端、管理端、工具脚本依赖混装到同一个 `package.json`
5. 为了图省事把 `playwright`、`next`、`antd` 之类的依赖统一装到根目录

---

## 5. 执行规则

后续新增 Node.js 工具或前端子工程时，必须同时满足：

1. 自己目录下有独立 `package.json`
2. 自己目录下安装依赖
3. 自己目录下维护锁文件
4. 命令执行时显式进入该目录，或使用 `pnpm --dir "<目录>" ...`

---

## 6. 当前结论

从现在开始，CheapAI 的 Node.js 依赖边界明确为：

1. `src/frontend/web-public/` 只管理用户端依赖
2. `src/frontend/web-admin/` 只管理管理端依赖
3. `tools/` 只管理脚本工具依赖
4. 仓库根目录不再承担任何 Node.js 包安装职责
