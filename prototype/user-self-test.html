Test Before Recharge

怀疑这个站不靠谱？先测，再决定

自助测试页应让用户明确知道自己输入什么、平台会返回什么、以及平台不会保存什么。页面右侧直接显示最近一次测试结果，避免来回跳转。

输入：站点地址 / API Key / 模型 输出：可用性 / 速度 / 风险

测试结论范围

能不能连通可测
返回快不快可测
有没有风险迹象可测
输入区

发起一次测试

原型中默认使用简洁三字段，避免把页面变成“高级设置表单”。

平台仅在当前测试任务内使用 API Key，不做持久化存储；日志中仅保留脱敏片段。正式实现时需要频控、防滥用和异常审计。

测试流程可视化

这里不是技术实现图，而是用户感知的流程，帮助他理解这个功能值不值得信任。

1. 输入测试参数 站点地址、API Key、模型名
开始
2. 发起真实请求 检测能否调用、返回速度、响应结构
执行
3. 应用反造假规则 检查缓存、降级、偷换、伪造迹象
分析
4. 输出可读结论 返回成功率、速度、风险标签和证据摘要
完成
